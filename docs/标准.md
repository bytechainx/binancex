# 类型层标准与当前限制

## 合成夹具

**夹具为合成样本，非真实源数据，不构成证据。** 夹具中的数值不能表述为实测结果、源核验通过或授权签核。

夹具文件须显式标记合成：JSON 外层使用 `_synthetic: true` 与说明字段，实际 wire 响应放在 payload 中；测试只将 payload 传入族解析器。若将标记混入源对象，严格解析应拒绝该未知字段。内联样本在相邻注释或文档中明确标记合成。字段名、层级与类型以冻结响应树为准。

## 冻结合同

元仓库 `specs/binancex/contracts/response-structures.json` 登记 92 个响应结构：Spot 19、USDM 35、COINM 26、Options 12。此数字是合同清单覆盖数，不是本 crate 的独立解析函数数量，也不是运行采集能力声明。具体导出映射由 `type-map.json` 决定。

`open_points` 保留源页面差异与待补证项；完成结构冻结不代表开放点关闭。变更字段或解释前，应补充源证据并按元仓库流程更新合同，再修改实现。

逐组必填字段、批次身份候选及证据定位见 [响应字段策略清单](响应字段策略.md)。

## 当前开放点与行为

| 范围 | 冻结合同的开放点 | 当前类型层行为 |
| --- | --- | --- |
| 四族 exchangeInfo filters；Spot exchangeFilters | filterType 与各变体字段归属未逐项核实，部分变体只列名称 | 只接受已冻结字段，使用可选字段并集；尚未验证判别值与字段组合，不能据此宣布过滤器语义完整 |
| Spot exchangeInfo；COINM exchangeInfo；Options exchangeInfo | count 层级推断、permissionSets 内层类型、可选 sors、COINM 空嵌套数组异常示例、Options 两层 minQty/maxQty、timezone 层级 | 沿冻结树保留层级与类型；不将示例异常扩大为任意 JSON，也不消除原合同中的推断标记 |
| USDM 001/013/015/023/026/027/028/031；Spot 012–016 | 数组元素由对象形推断；部分数组触发条件未明示；Spot 示例 number 与字段表 string 冲突 | 双形响应保留 Object/Array，元素共用冻结形状；不推导请求参数，字段表声明 string 的位置拒绝 JSON number |
| USDM 023 保险余额 | assets 元素字段未展开，symbols 与资产数组语义关系待核实 | assets 元素目前是拒绝未知字段的空对象，非空未知结构失败；空数组或空对象通过不代表资产内容已被理解 |
| USDM 034/035；Spot 019 | marketSchedules 键集未封闭；fromIsBase 仅见捕获；referencePriceCalculation 条件字段归属待核实 | 日程入口只接受六个已有证据的市场键；fromIsBase 按冻结字段保留；条件字段按单对象可选字段保留，尚未验证 calculationType 对应组合 |

USDM 034 的值类型使用 map，但 `parse_usdm_trading_schedule` 仅放行 `EQUITY`、`COMMODITY`、`KR_EQUITY`、`HK_EQUITY`、`CN_EQUITY`、`FX`；新键返回 `UnknownField`，须先补证再扩充。完整开放点原文、端点 ID 与证据定位以元仓库合同为准。

## 结构检查与语义检查

具体解析入口递归要求对象使用 JSON 映射，拒绝用位置数组代替对象；有已登记字段的对象拒绝空对象，保险 assets 中尚无已登记字段的空对象仍按冻结树保留。未知字段失败，数组或元组中的结构错误导致整个解析结果失败。双形响应入口先选择根形态，再对具体类型执行上述检查；直接调用类型的 serde 反序列化不等同于入口验收。

整数使用 `i64`，越界及整数位置的浮点表示返回 `LossyNumeric`；数值字符串保留原文，JSON number 保留无损表示。对象未知键返回 `UnknownField`；字段类型、对象形态和元组长度不符返回 `SchemaMismatch`。USDM deliveryPrice 入口额外检查原始 wire 形态，拒绝用对象伪装 JSON number，并保留合法数字的无损表示。

12 组 Kline 已按开盘时间检测批内重复并原子返回 `IdentityConflict`：Spot Kline、USDM 的 Kline/ContinuousKline/IndexPriceKline/MarkPriceKline/PremiumIndexKline、COINM 对应五组、Options Kline。此结论不扩展到 Spot UiKline 或其他尚未裁决批次身份的对象响应。

`parse_spot_avg_price` 已检查关键字段 `price`、`closeTime`：缺键返回 `Missing`，显式 `null` 或类型错误返回 `Invalid`；`closeTime` 的小数或指数形式也由该入口预检拒绝。其余类型组的命名必填字段集合尚未统一裁决。`referencePrice` 仍允许缺失或 `null`，禁止代为填零。

当前大部分对象字段为 `Option<T>`，非空对象中的其他缺字段仍可形成 `None`。其他对象批次的身份判定、时间单位及合法区间、数量单位、filterType 与 calculationType 对应组合尚未完整裁决。使用值对象前仍须依据冻结合同完成语义校验，不能把反序列化成功当作全部条件已通过。

`Decimal` / `Quantity` 是单独的受检构造入口，四族 wire string 字段不会自动经过它们。源响应签名、原始数量符号和单位解释应保持可追溯；禁止经 `f64` 中转或悄悄取绝对值。

## 测试与验收

当前 P6 仍有上述解析与语义校验缺口，尚不可宣布验收完成。本文记录的是当前实现状态，不是对冻结合同要求的豁免。

验收区分单元测试、集成测试与契约测试。必要负向场景包括未知字段、缺失必需项、非法时间戳、重复身份、整数溢出及数量符号不可判定；对应实现缺失时登记缺口，不能仅测试现有宽松行为后宣称通过。

门禁命令见 [README](../README.md#门禁)。通过 fmt、clippy、test 或 package 不能关闭源合同开放点，也不改变 `production_decision = NO-GO`。
